# 3차시: 내 숫자 이미지 예측

## 수업 개요

이번 차시에서는 2차시에서 학습한 MNIST 숫자 분류 모델을 사용해 직접 만든 숫자 이미지를 예측합니다. 2차시가 `모델을 학습시키는 과정`이었다면, 3차시는 `학습된 모델을 실제로 사용하는 과정`입니다.

AI 프로젝트에서 모델을 학습시키는 것만큼 중요한 단계가 바로 예측입니다. 모델이 아무리 학습 데이터에서 높은 정확도를 보여도, 실제로 사용자가 만든 새로운 이미지에서 잘 작동하지 않으면 좋은 모델이라고 보기 어렵습니다.

이번 수업에서는 직접 손으로 쓴 숫자 이미지를 준비하고, 그 이미지를 모델이 이해할 수 있는 형태로 바꾼 뒤, 모델이 어떤 숫자로 판단하는지 확인합니다. 그리고 모델이 틀렸을 때 왜 틀렸는지 함께 분석합니다.

## 학습 목표

수업이 끝난 뒤 학습자는 다음을 설명하거나 수행할 수 있어야 합니다.

- 학습된 모델을 저장하고 다시 불러오는 이유를 설명할 수 있습니다.
- 직접 만든 숫자 이미지를 예측용 입력으로 사용할 수 있습니다.
- 이미지 크기 변경, 흑백 변환, 색상 반전, 정규화의 필요성을 이해할 수 있습니다.
- 모델의 예측 결과와 확신도를 해석할 수 있습니다.
- 모델이 틀렸을 때 가능한 원인을 데이터 관점에서 설명할 수 있습니다.
- 좋은 예측 결과를 얻기 위한 이미지 준비 조건을 말할 수 있습니다.

## 1. 학습된 모델을 사용한다는 것

### 1.1 학습과 예측의 차이

AI 모델을 다룰 때는 크게 두 단계가 있습니다.

```text
학습: 데이터를 보고 패턴을 배우는 단계
예측: 배운 패턴을 이용해 새로운 데이터를 판단하는 단계
```

2차시에서는 MNIST 데이터셋을 이용해 모델을 학습했습니다. 모델은 손글씨 숫자 이미지 60,000장을 보면서 숫자의 모양적 특징을 배웠습니다.

3차시에서는 이미 학습된 모델을 불러와 새로운 이미지를 넣어봅니다. 이때 새로운 이미지는 모델이 학습 중에 본 적 없는 이미지입니다. 따라서 이 과정은 모델이 실제 상황에서 얼마나 잘 작동하는지 확인하는 중요한 단계입니다.

### 1.2 모델 저장 파일

2차시 코드에서는 학습이 끝난 모델을 다음 위치에 저장합니다.

```text
models/mnist_digit_cnn.keras
```

이 파일에는 모델 구조와 학습된 값들이 들어 있습니다. 모델 구조는 어떤 계층으로 이루어져 있는지를 의미하고, 학습된 값은 모델이 데이터에서 배운 패턴 정보를 의미합니다.

모델을 저장하면 좋은 점은 다음과 같습니다.

- 매번 처음부터 다시 학습하지 않아도 됩니다.
- 학습된 모델을 다른 코드에서 불러와 사용할 수 있습니다.
- 나중에 직접 만든 이미지나 새로운 이미지에 적용할 수 있습니다.
- 모델을 다른 사람에게 공유할 수 있습니다.

### 1.3 모델 불러오기

프로젝트의 [src/02_predict_digit_image.py](../src/02_predict_digit_image.py) 파일에서는 저장된 모델을 다음 코드로 불러옵니다.

```python
model = tf.keras.models.load_model(MODEL_PATH)
```

여기서 `MODEL_PATH`는 다음 파일을 가리킵니다.

```python
MODEL_PATH = Path("models/mnist_digit_cnn.keras")
```

만약 이 파일이 없다면 예측을 할 수 없습니다. 따라서 3차시 실습 전에 반드시 2차시의 학습 코드를 먼저 실행해야 합니다.

```powershell
python src\01_train_mnist_digits.py
```

## 2. 직접 쓴 숫자 이미지 준비하기

### 2.1 어떤 이미지가 필요한가

이번 실습에서는 직접 만든 숫자 이미지가 필요합니다. 예를 들어 그림판, 태블릿, 스마트폰 메모 앱, 종이에 쓴 숫자를 찍은 사진 등을 사용할 수 있습니다.

다만 모델은 MNIST 데이터셋으로 학습되었습니다. MNIST 이미지는 다음과 같은 특징을 가집니다.

- 숫자 하나만 들어 있습니다.
- 숫자가 이미지 중앙 근처에 있습니다.
- 배경과 숫자의 대비가 큽니다.
- 이미지 크기는 `28 x 28`입니다.
- 흑백 이미지입니다.
- 대체로 어두운 배경에 밝은 숫자 형태입니다.

따라서 직접 만든 이미지도 이 조건에 가까울수록 예측이 잘 됩니다.

### 2.2 좋은 입력 이미지 조건

좋은 예측 결과를 얻으려면 다음 조건을 지키는 것이 좋습니다.

| 조건 | 이유 |
| --- | --- |
| 숫자 하나만 포함 | 모델은 숫자 하나를 분류하도록 학습됨 |
| 숫자가 중앙에 위치 | MNIST 숫자들이 대체로 중앙에 있기 때문 |
| 배경이 단순함 | 배경 무늬가 있으면 모델이 혼란스러울 수 있음 |
| 숫자와 배경 대비가 큼 | 픽셀 패턴이 뚜렷해야 특징을 찾기 쉬움 |
| 너무 작거나 너무 크지 않음 | 크기가 지나치게 다르면 MNIST와 달라짐 |
| 흐리지 않음 | 흐린 이미지는 선과 곡선 특징이 약해짐 |

예를 들어 흰 배경에 검은색 굵은 펜으로 숫자 하나를 크게 쓰면 좋은 입력 이미지가 될 수 있습니다.

### 2.3 나쁜 입력 이미지 예시

다음과 같은 이미지는 모델이 틀릴 가능성이 높습니다.

- 숫자가 너무 작게 적힌 이미지
- 숫자가 이미지 구석에 치우친 이미지
- 여러 숫자가 함께 들어 있는 이미지
- 배경에 줄, 그림, 글자 등이 많은 이미지
- 사진이 흐리거나 그림자가 심한 이미지
- 숫자가 너무 기울어진 이미지
- MNIST에 없는 글씨체나 장식이 많은 숫자

모델이 틀렸다고 해서 항상 모델만 문제가 있는 것은 아닙니다. 입력 이미지가 모델이 학습한 데이터와 너무 다르면 예측이 어려워질 수 있습니다.

## 3. 이미지 전처리 이해하기

### 3.1 왜 전처리가 필요한가

학습된 모델은 특정한 입력 형태를 기대합니다. MNIST 모델은 다음 형태의 이미지를 입력받도록 만들어졌습니다.

```text
28 x 28 x 1
```

하지만 사용자가 준비한 이미지는 크기와 색상 형식이 제각각일 수 있습니다.

예를 들어 다음과 같은 이미지가 들어올 수 있습니다.

- `500 x 500` 크기의 PNG 이미지
- 스마트폰으로 찍은 컬러 사진
- 흰 배경에 검은 숫자
- 검은 배경에 흰 숫자
- 여백이 많은 이미지

이 이미지를 그대로 모델에 넣으면 오류가 나거나 예측 품질이 낮아질 수 있습니다. 그래서 예측 전에 모델이 이해할 수 있는 형태로 바꾸는 과정이 필요합니다. 이것이 전처리입니다.

### 3.2 이미지 열기와 흑백 변환

코드에서는 Pillow 라이브러리를 사용해 이미지를 엽니다.

```python
image = Image.open(image_path).convert("L")
```

`convert("L")`은 이미지를 흑백으로 바꾸는 코드입니다. MNIST 모델은 흑백 이미지로 학습되었기 때문에 예측할 이미지도 흑백으로 맞춥니다.

컬러 이미지는 픽셀 하나가 RGB 세 개의 숫자로 표현됩니다.

```text
[R, G, B]
```

흑백 이미지는 픽셀 하나가 밝기 숫자 하나로 표현됩니다.

```text
밝기 값 하나
```

따라서 흑백 변환은 모델 입력을 단순하게 맞추는 과정입니다.

### 3.3 이미지 크기 맞추기

MNIST 모델은 `28 x 28` 크기의 이미지를 입력받습니다. 그래서 직접 만든 이미지도 같은 크기로 바꿔야 합니다.

```python
image = ImageOps.fit(image, (28, 28), method=Image.Resampling.LANCZOS)
```

이 코드는 이미지를 `28 x 28` 크기로 맞춥니다.

이미지 크기 조정은 매우 중요합니다. 모델은 학습할 때 `28 x 28` 숫자 배열을 보았기 때문에, 예측할 때도 같은 구조의 숫자 배열을 받아야 합니다.

### 3.4 색상 반전

MNIST는 대체로 어두운 배경에 밝은 숫자 형태입니다. 하지만 사용자가 만든 이미지는 흰 배경에 검은 숫자인 경우가 많습니다.

예를 들어 그림판에서 흰 배경에 검은 숫자를 그리면 다음과 같습니다.

```text
배경: 밝음
숫자: 어두움
```

MNIST와는 반대입니다.

그래서 코드에서는 이미지 평균 밝기를 보고 필요하면 색상을 반전합니다.

```python
pixels = np.array(image).astype("float32")

if pixels.mean() > 127:
    pixels = 255 - pixels
```

평균 밝기가 127보다 크다는 것은 이미지 전체가 밝은 편이라는 뜻입니다. 흰 배경 이미지일 가능성이 큽니다. 이 경우 `255 - pixels`로 색을 뒤집어 어두운 배경에 밝은 숫자 형태로 바꿉니다.

### 3.5 정규화

이미지 픽셀 값은 원래 `0`부터 `255` 사이입니다. 모델은 학습할 때 픽셀 값을 `0`부터 `1` 사이로 정규화한 이미지를 사용했습니다.

따라서 예측할 이미지도 똑같이 정규화해야 합니다.

```python
pixels = pixels / 255.0
```

학습 때와 예측 때의 전처리 방식이 다르면 모델이 혼란스러워질 수 있습니다. 이것은 매우 중요한 원칙입니다.

```text
학습할 때 사용한 전처리와 예측할 때 사용하는 전처리는 최대한 같아야 한다.
```

### 3.6 모델 입력 형태로 바꾸기

마지막으로 이미지를 모델에 넣을 수 있는 shape로 바꿉니다.

```python
return pixels.reshape(1, 28, 28, 1)
```

여기서 각 숫자의 의미는 다음과 같습니다.

| 위치 | 값 | 의미 |
| --- | ---: | --- |
| 첫 번째 | 1 | 이미지 1장을 예측함 |
| 두 번째 | 28 | 이미지 높이 |
| 세 번째 | 28 | 이미지 너비 |
| 네 번째 | 1 | 흑백 채널 |

모델은 여러 이미지를 한 번에 예측할 수도 있기 때문에, 이미지가 1장이어도 맨 앞에 `1`이라는 차원이 필요합니다.

## 4. 예측 결과 해석하기

### 4.1 예측 실행

전처리된 이미지를 모델에 넣으면 예측 결과를 얻을 수 있습니다.

```python
probabilities = model.predict(prepared_image)[0]
```

이 결과는 숫자 하나가 아니라 10개의 값입니다. 각 값은 `0`부터 `9`까지 각 숫자일 가능성을 의미합니다.

예를 들어 다음과 같은 결과가 나올 수 있습니다.

```text
0: 0.01
1: 0.02
2: 0.03
3: 0.80
4: 0.01
5: 0.05
6: 0.01
7: 0.02
8: 0.04
9: 0.01
```

가장 큰 값은 `3`의 `0.80`입니다. 따라서 모델은 이 이미지를 숫자 `3`으로 예측합니다.

### 4.2 최종 예측 숫자 구하기

가장 높은 확률을 가진 숫자를 찾기 위해 다음 코드를 사용합니다.

```python
predicted_digit = int(np.argmax(probabilities))
confidence = float(probabilities[predicted_digit])
```

`np.argmax`는 가장 큰 값의 위치를 찾습니다. 출력 배열의 위치가 곧 숫자 클래스입니다.

```text
위치 0 -> 숫자 0
위치 1 -> 숫자 1
위치 2 -> 숫자 2
...
위치 9 -> 숫자 9
```

`confidence`는 모델이 선택한 숫자에 대해 얼마나 높은 가능성을 주었는지 나타냅니다.

### 4.3 확신도 해석

모델 출력의 가장 큰 확률을 확신도처럼 해석할 수 있습니다.

```text
예측 결과: 3
확신도: 92.5%
```

이 결과는 모델이 입력 이미지를 숫자 `3`으로 판단했고, 그 판단에 대해 꽤 높은 점수를 주었다는 뜻입니다.

하지만 확신도가 높다고 항상 정답인 것은 아닙니다. 모델은 틀린 답에도 높은 확신을 가질 수 있습니다. 특히 입력 이미지가 학습 데이터와 많이 다르면 이런 일이 생길 수 있습니다.

반대로 확신도가 낮다면 모델이 헷갈리고 있다는 뜻일 수 있습니다.

```text
3일 가능성: 45%
8일 가능성: 42%
```

이런 경우 최종 예측은 `3`이지만, 모델 입장에서는 `8`과 매우 헷갈리는 상황입니다.

### 4.4 숫자별 확률 보기

프로젝트 코드는 숫자별 확률을 모두 출력합니다.

```python
for digit, probability in enumerate(probabilities):
    print(f"  {digit}: {probability:.2%}")
```

이 출력은 수업에서 매우 유용합니다. 단순히 정답만 보는 것이 아니라 모델이 어떤 숫자와 헷갈렸는지 볼 수 있기 때문입니다.

예를 들어 실제 숫자가 `9`인데 결과가 다음과 같다면,

```text
4: 38%
9: 40%
```

모델은 `9`를 맞히긴 했지만 `4`와 매우 헷갈렸다고 해석할 수 있습니다.

```python
plt.show()
```

여기서 보이는 이미지는 원본 이미지가 아니라 모델에 실제로 들어간 `28 x 28` 전처리 이미지입니다. 이 이미지를 보는 것이 중요합니다.

원본에서는 숫자가 잘 보였더라도, `28 x 28`로 줄인 뒤에는 숫자가 뭉개질 수 있습니다. 모델은 원본이 아니라 전처리된 이미지를 보고 판단합니다.

## 6. 틀렸을 때 원인 생각해보기

### 6.1 모델이 틀리는 것은 자연스러운 일

AI 모델은 항상 맞히지 않습니다. 특히 직접 만든 숫자 이미지는 MNIST와 조건이 다를 수 있으므로 틀릴 수 있습니다.

모델이 틀렸을 때 중요한 태도는 `왜 틀렸을까`를 분석하는 것입니다. 틀린 결과는 실패가 아니라 모델과 데이터의 관계를 이해할 수 있는 좋은 학습 자료입니다.

### 6.2 입력 이미지 문제

가장 먼저 확인할 것은 입력 이미지입니다.

다음 질문을 해볼 수 있습니다.

- 숫자가 이미지 중앙에 있나요?
- 숫자가 너무 작거나 너무 크지 않나요?
- 배경이 단순한가요?
- 숫자와 배경의 대비가 충분한가요?
- 이미지가 흐리거나 그림자가 많지 않나요?
- 숫자 하나만 들어 있나요?

입력 이미지가 MNIST와 너무 다르면 모델이 잘못 예측할 가능성이 높습니다.

### 6.3 전처리 결과 문제

원본 이미지가 좋아 보여도 전처리 후 결과가 나쁠 수 있습니다.

예를 들어 다음과 같은 문제가 생길 수 있습니다.

- 크기를 줄이면서 숫자 선이 너무 얇아짐
- 여백이 많아서 숫자가 작아짐
- 색상 반전이 예상과 다르게 적용됨
- 배경 그림자가 숫자처럼 남음
- 사진의 노이즈가 픽셀 패턴을 방해함

그래서 전처리된 `28 x 28` 이미지를 반드시 확인해야 합니다.

### 6.4 모델의 한계

모델 자체의 한계도 있습니다. 이 모델은 MNIST 손글씨 숫자에 맞춰 학습되었습니다. 따라서 다음과 같은 입력에는 약할 수 있습니다.

- 디지털 폰트 숫자
- 장식적인 글씨체
- 너무 굵거나 너무 얇은 숫자
- 사진으로 찍은 복잡한 배경의 숫자
- 숫자가 회전되어 있는 이미지

모델은 세상의 모든 숫자를 이해한 것이 아니라, MNIST와 비슷한 픽셀 패턴을 학습한 것입니다.

### 6.5 자주 발생하는 오해

수업에서 학습자가 자주 하는 오해는 다음과 같습니다.

| 오해 | 설명 |
| --- | --- |
| 사람이 보면 쉬운데 AI도 당연히 맞혀야 한다 | AI는 사람처럼 의미를 이해하지 않고 픽셀 패턴으로 판단함 |
| 확신도가 높으면 무조건 정답이다 | 모델은 틀린 답에도 높은 확신을 줄 수 있음 |
| 모델이 틀리면 학습이 실패한 것이다 | 입력 조건이나 전처리 차이 때문에 틀릴 수도 있음 |
| 이미지가 크면 더 잘 맞힌다 | 모델 입력 크기는 28 x 28로 고정되어 있음 |
| 예측만 하면 AI 프로젝트가 끝난다 | 결과 분석과 개선이 중요함 |

## 7. 개선 실험 아이디어

### 7.1 같은 숫자를 여러 방식으로 써보기

학습자에게 같은 숫자를 여러 번 써보게 합니다.

예를 들어 숫자 `7`을 다음처럼 다양하게 써볼 수 있습니다.

- 곧은 7
- 가운데 선이 있는 7
- 기울어진 7
- 아주 얇은 7
- 아주 굵은 7

그 후 모델이 어떤 형태를 잘 맞히고 어떤 형태를 헷갈리는지 비교합니다.

### 7.2 이미지 위치 바꿔보기

숫자를 중앙에 둔 이미지와 구석에 둔 이미지를 비교합니다.

질문합니다.

- 중앙에 있을 때 더 잘 맞히나요?
- 구석에 있을 때 확신도가 떨어지나요?
- MNIST 데이터셋의 숫자 위치와 어떤 관련이 있을까요?

### 7.3 배경 바꿔보기

흰 배경, 검은 배경, 회색 배경, 줄이 있는 배경에서 실험해봅니다.

질문합니다.

- 배경이 복잡하면 결과가 어떻게 달라지나요?
- 색상 반전이 제대로 작동하나요?
- 모델은 배경과 숫자를 잘 구분하나요?

### 7.4 손글씨와 폰트 비교하기

손으로 쓴 숫자와 컴퓨터 폰트 숫자를 비교해봅니다.

MNIST는 손글씨 데이터셋이므로, 폰트 숫자가 오히려 잘 안 맞을 수 있습니다. 이 실험은 모델이 `일반적인 숫자의 의미`가 아니라 `학습 데이터와 비슷한 패턴`을 배운다는 점을 이해시키는 데 좋습니다.

## 11. 마무리 정리

이번 차시에서는 학습된 MNIST 모델을 불러와 직접 만든 숫자 이미지를 예측하는 과정을 배웠습니다.

예측을 잘 수행하려면 모델이 학습할 때 사용한 데이터 형식과 예측할 때 사용하는 데이터 형식을 최대한 맞춰야 합니다. MNIST 모델은 `28 x 28` 크기의 흑백 이미지, 정규화된 픽셀 값, 어두운 배경에 밝은 숫자 형태에 익숙합니다.

따라서 직접 만든 이미지는 흑백 변환, 크기 조정, 필요할 경우 색상 반전, 정규화, shape 변환 과정을 거쳐야 합니다. 모델이 출력하는 숫자별 확률을 보면 최종 예측뿐 아니라 어떤 숫자와 헷갈리는지도 알 수 있습니다.

모델이 틀렸을 때는 단순히 실패로 보지 말고, 입력 이미지와 전처리 결과, 모델의 학습 데이터 차이를 함께 분석해야 합니다. 이 과정이 AI 프로젝트에서 모델을 이해하고 개선하는 중요한 출발점입니다.

다음 차시에서는 손글씨 숫자 분류에서 벗어나 실제 사진 데이터인 개와 고양이 이미지 분류로 확장합니다. 이때는 사진 데이터의 복잡성, 데이터 폴더 구조, 과적합, 데이터 증강 같은 새로운 개념을 배우게 됩니다.
